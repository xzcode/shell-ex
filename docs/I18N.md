# Interface localization

Shell EX supports Simplified Chinese and English, with System default as the initial preference.
Non-Chinese system locales fall back to English. Choose a language in Settings → Appearance → Interface language, and save. The preference is stored locally in the WebView. Changing it does not reset the React application, host configuration, SSH sessions, credentials, or file paths.

- Translation entry point: apps/desktop/src/i18n.ts
- English catalog: apps/desktop/src/locales/en.ts
- Source Chinese messages are the lookup keys and Chinese fallback. The English catalog covers the workbench, connection editor, settings, SFTP, remote editor, transfers, snippets, tunnels, Docker, monitor, terminal controls, and known application-generated diagnostics.
- Preserve the numbered placeholders in translations. Never translate user-defined host/group names, commands, paths, raw SSH output or external diagnostic details. New locales should use the same keys and be registered in the locale resolver and settings selector.
- Dynamic backend messages and third-party native controls may still use their original language. Do not claim full localization of third-party libraries or remote output.

Run npm run typecheck, npm run build, and npm run test:ui from apps/desktop. The existing Chinese workbench regression uses zh-CN explicitly; i18n.spec.ts checks English system locale, manual language switching, persistence, and unchanged saved host data.

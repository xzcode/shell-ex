## 已实现的安全与交互约束

- 文件管理：规范化目录、排序、创建目录、不覆盖重命名、删除文件或空目录、权限修改。
- 编辑器：UTF-8 文本，最多 5 MiB；SHA-256 与元数据形成版本令牌，保存前再次校验。
- 传输：有界并发，可调整为 1～8；上传与下载先写入同目录临时文件；续传检查完整源文件与已传输前缀，完成后检查 SHA-256。
- 覆盖前再次核对已有目标的元数据和内容；取消与失败不把部分内容当作完成文件发布。
- 目录复制：先预览，再明确选择跳过或覆盖。计划保存在后端，最多保留 8 个，5 分钟过期；开始前重新检查源文件和目录。
- 目录复制上限：1,000 个文件、2,048 个总条目、32 层目录；不跟随符号链接；拒绝设备、管道、套接字。目录合并与逐文件传输可能部分完成，返回值包含已排队数量、跳过数量与具体错误。
- Windows 分支额外把 junction 与其它 reparse point 当作链接拒绝，避免把目录复制重定向到用户选择的树之外；并校验 Windows 保留文件名。
- Linux 监控独立于终端，读取固定命令；进程操作只接受数值 PID 和 TERM/KILL。Docker 操作不拼接任意操作名或容器名。

## 发布前仍需知道的边界

1. **跨平台实机**：目前实际集成验证在 Linux 完成。macOS、Windows 的文件对话框、系统权限与文件系统行为需要对应平台的构建和实机验证，不能据此声称已经通过。
2. **原子覆盖能力**：远程覆盖需要服务器支持 `posix-rename@openssh.com`。不支持时保留原文件并返回错误；编辑器可另存为新路径，不采用先删除原文件再重命名的回退。
3. **本地新文件发布**：使用同文件系统的硬链接实现不覆盖发布；文件系统不支持时安全失败，保留已校验的临时文件并给出路径。已有本地目标使用同目录重命名替换。Rust 官方说明见 [rename](https://doc.rust-lang.org/stable/std/fs/fn.rename.html) 与 [hard_link](https://doc.rust-lang.org/stable/std/fs/fn.hard_link.html)。
4. **续传生命周期**：暂停、失败后的恢复属于本次应用进程；尚无应用重启后恢复队列的持久化协议。异常退出可能留下 `.shell-ex-*.part` 文件。断线导致取消清理失败时，任务错误中给出残留路径。
5. **并发写入**：冲突检查采用乐观校验。SFTP 没有文件内容的原子 compare-and-swap，因此与其它程序同时修改同一路径仍存在最后一次检查到重命名之间的窗口；不宣称提供跨进程文件锁。
6. **元数据**：覆盖已有远程文件时尝试保留 POSIX 权限、UID/GID，失败则不替换原文件。ACL、扩展属性、文件能力和 SELinux 标签没有完整复制。新下载文件默认采用本地受限权限，不自动标为可执行。
7. **监控范围**：当前为 Linux，磁盘展示根文件系统，网络为非回环接口计数汇总，进程列表最多 60 项。CPU 首次采样显示空值，下一次才计算使用率。
8. **协议与权限**：目录和文本编辑依赖 SFTP 权限；没有静默 sudo 提权。远程 `fsync` 是否真正执行依赖服务端扩展，不把普通关闭文件等同于断电后持久性承诺。

本文件没有桌面程序截图或 macOS 签名安装包证据；相关构建与界面验收应引用对应记录。

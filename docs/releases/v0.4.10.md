# Shell EX v0.4.10 — Monitor docking stability and compact snippets

- Reuses the secondary monitoring WebView instead of destroying it while a dock command or telemetry callback may still be in flight. The native close button follows the same hide/dock path. The main window still controls application shutdown. Docking disables duplicate actions and rejects stale context updates.
- CPU trends display 0–100% ticks and actual sample timestamps. Network trends use a shared, adaptive rate scale and explicit B/s, KB/s, MB/s or larger units. Empty and initial single-sample histories do not fabricate measurements.
- Top processes, disk mounts and the all-process dialog have independently resizable header columns, double-click reset, keyboard resizing and local width preferences. Long paths remain available in tooltips, and wider tables scroll horizontally.
- Quick commands use compact cards with a maximum width of 340 logical pixels and automatic multi-column layout. Insert and Copy are grouped just below the command; existing edit/delete actions remain in the header. Long commands wrap and scroll within their card. Insert is disabled without a connected terminal.

The suspected macOS docking crash is addressed by avoiding live WebView destruction; the precise crash stack and actual Finder/AppKit behavior still require native device verification. Browser fixtures check UI and IPC state transitions, not real native-window destruction.

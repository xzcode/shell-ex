# Shell EX v0.3.1 — 保存 SSH 密码无需额外主密码

## 体验修正

在「新建 SSH 连接 → 基本信息」中，**密码保存位置默认选择「本地自动加密保存」**。输入服务器 SSH 密码后直接保存连接，后续打开 Shell EX 不再询问本地密码库主密码。应用会首次自动生成随机 256 位安装专属密钥。原有系统凭据库及“仅本次使用”选项仍保留，旧的 Argon2id 主密码库仅用于兼容历史记录（不会清除或自动重置旧凭据）。

## 存储机制

- 新增 `auto-vault.sqlite3`（AES-256-GCM 密文）与 `auto-vault.key`（本机随机密钥），保存在 Tauri 应用数据目录中。两者使用分开的本地文件，Unix 系统限制目录为 0700、文件为 0600；Windows 依赖用户目录的账户访问控制。
- 每条 SSH 凭据单独使用随机 nonce，并使用主机 UUID 绑定认证附加数据（AAD）。不会将 SSH 密码明文写入主机配置或普通 SQLite 表。
- 密钥丢失时不会自动创建另一把密钥覆盖记录；请保护应用目录及加密备份。
- **安全边界：这种便利模式不等同于独立主密码保护。** 任何可同时取得密钥文件和加密数据库的攻击者，都可能解密已保存的服务器密码；应保护系统登录和磁盘安全。
- **旧版本兼容：** `credentialStore=system` 继续从系统 Keychain 读取，`credentialStore=local` 仍使用旧版主密码加密库。由旧版改用自动模式时，如能从原保存位置读取凭据则迁移；否则可重新输入一次 SSH 密码，不删除旧密文或静默重置。

## 验证

目标测试覆盖 Rust 本地加密库的密文持久化、跨主机替换攻击检测、丢失密钥保护；React 前端输入与下拉框默认选中、旧版兼容及原有 SSH/SFTP 行为。实际通过状态以 CI 或开发交接文档中的运行记录为准。

原 v0.3.0 发布草稿不包含本次改动；不要误把旧 DMG 标记为 v0.3.1。原构建来源 `a247fc1` 不应更名为新版。

# Shell EX v0.4.14 — Storage, disk I/O and process monitoring

- Replace the mount-point card with Storage: default to unique local and network/shared filesystems. Classify filesystem types and suppress overlay, tmpfs, loop images and repeated device mounts. Show source, mount path, type, available/total space and usage. Filter local, network or all sampled capacity-bearing mounts.
- Use Linux mountinfo and df for filesystem capacity. The root indicator describes the root filesystem, not physical-disk capacity. Do not sum shared storage or multiple layers. Time-limited df fallback and collection bounds report partial mount results.
- Independently sample whole block devices from sysfs and /proc/diskstats (including presented cloud disks and logical devices). Calculate read/write throughput, IOPS, busy time, read/write/combined latency and queue depth from counter deltas. Device switching retains separate recent throughput and utilization series. First samples, resets and missing metrics remain unavailable; never aggregate physical and logical layers. Network filesystem capacity is shown, but NFS-specific I/O is not collected.
- Collect visible processes using direct RSS and /proc/PID/stat CPU ticks, clock frequency, uptime and process start identity. Show per-interval CPU (100% is one logical core), rather than lifetime ps averages. PID reuse and counter resets invalidate the interval. Switch top-five CPU/RSS ranking, search and sort the full collected list with pagination and adjustable columns. The list is bounded to 10,000 processes and a transport byte budget; report truncation explicitly. Restricted procfs visibility and unsupported utilities can limit telemetry.
- Both docked and detached monitoring reuse the same implementation; detached mode remains read-only. No installed monitoring agent, new server dependency or elevated privilege is required on normal GNU/Linux systems. Some minimal Linux environments may lack compatible df/ps/getconf.

References: Linux kernel I/O statistics (https://docs.kernel.org/admin-guide/iostats.html), proc_pid_stat(5) (https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html), and GNU df documentation (https://www.gnu.org/software/coreutils/manual/html_node/df-invocation.html).

Native packaging and macOS device validation remain separate from browser and loopback SSH tests.

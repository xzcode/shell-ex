# Shell EX v0.4.18 — Password-authorized sudo and privileged archive downloads

## New functionality

- Prefer existing passwordless sudo authorization; when denied, offer an explicit password dialog bound to the current SSH session. Incorrect passwords are rejected and retries require user action. Never save the sudo password to connection settings or the credential vault.
- Keep the password in zeroizing backend memory only while its file capability is active, including independent raw SFTP authentication for atomic replacement. Send it to SSH stdin only after detecting the generated sudo prompt, never in command arguments.
- Enable privileged server-side `.tar.gz` archive downloads using a fixed `/usr/bin/tar` operation. Validate canonical sibling selections, quote literal arguments and create a private root-owned staging directory with mode `0700` in the original SFTP mkdir request.
- Label elevated transfers, cancel pending archive preparation and unfinished transfers when revoking the file capability, and attempt cleanup before closing SFTP. No arbitrary elevated command endpoint and no changes to the server's sudo configuration.

## Compatibility

The server must authorize the OpenSSH sftp-server path and, for elevated archives, `/usr/bin/tar`. Existing passwordless policies remain supported. Password-based sudo uses a non-PTY stdin prompt; MFA, `requiretty` and unsupported custom prompt protocols are not supported. A server allowing only passwordless SFTP may separately require authorization for tar. Abrupt disconnects or remote failures can prevent cleanup; private staging files may remain.

## Verification

The V4 development commit passed 42 core unit tests, 10 additional Rust authentication/integration tests, and 24 browser UI tests. The isolated loopback OpenSSH tests exercise actual password-required authorization, wrong-password rejection, atomic replacement, file and directory transfers, privileged archive downloads and revocation. Test-only sudo user and policy setup occurs exclusively on disposable GitHub-hosted runners. Native desktop packaging runs separately. Physical-device acceptance remains separate from CI.
